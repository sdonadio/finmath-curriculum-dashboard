# FinMath Curriculum Arena — data schema (frozen for the build)

Static site, vanilla ES5-compatible JS, no build step at runtime, GitHub Pages.
Program → concentration → course → week. Every course gets its own **deep** page.
All content is derived from the public FinMath site (course pages + syllabus PDFs)
and marked as such; illustrative code and questions are ours.

## Directory layout

```
FinMathCurriculumArena/
  SCHEMA.md                 this file
  site_params.js            THE ONLY file naming the institution / program / URLs
  program.js                degree rules, concentrations, quarters, course index
  courses/finm-XXXXX.js     one file per course (29)         → window.COURSES["FINM 33000"] = {...}
  skills.js                 GENERATED by tools/build_skills.py from courses/*.js
  index.html                program map + filters
  concentration.html?c=…    one template page, reads program.js
  course.html?c=FINM-33000  one template page, reads courses/*.js   (plus static course-finm-33000.html wrappers for deep links)
  skills.html               skills index (teaches / assumes)
  quarter.html              Autumn / Winter / Spring load view
  app.js  widgets.js  styles.css
  data/raw/                 harvested pages + syllabus text (committed, plain text)
  data/courses.csv          canonical inventory (harvest output)
  tools/                    harvest.py, build_skills.py, validate.py, make_course_pages.py, run_snippets.py
```


## courses/finm-XXXXX.js  (the deep page)

```js
window.COURSES = window.COURSES || {};
window.COURSES["FINM 33000"] = {
  code: "FINM 33000", slug: "finm-33000", title: "Options",
  instructor: "Roger Lee", quarter: "Autumn", units: 100,
  block: "core" | "computing" | "electives",
  concentrations: ["options-derivatives"],          // ids from program.js; [] for core/computing
  source: { page_url, syllabus_url, fetched: "2026-09-26" },
  tier: "B",                                        // v1: "B" = built from the public course page (no syllabus access)
  description: "…public description, lightly edited…",
  prerequisites: ["…"], textbooks: [{title, author, note}],
  skills_built: ["risk-neutral-pricing", …],        // kebab-case tags, shared vocabulary (see below)
  skills_assumed: ["measure-theoretic-probability", …],
  brushup: [{topic, why, resource}],                // 4–8 items: what to revise before week 1
  weeks: [                                          // 9–10 per quarter course; 5 for half-quarter (50-unit) courses if the syllabus says so
    { n: 1, title: "…", topics: ["…"],
      concepts: [ {name, explain (150–300 words, plain HTML allowed), formula (KaTeX string, optional),
                   code: {lang:"python"|"cpp"|"r", src, output}   // output = REAL stdout from tools/run_snippets.py
                 } ],                                // 3–5 concepts per week
      widget: {type, title, params}  | null,        // from the widget menu; ≥ 1 widget on ≥ 60 % of weeks
      pitfalls: ["…"],                              // 2–4
      check: [ {q, options[4], answer (index), why} ]  // 3–4 MCQs
    }, …
  ],
  interview: [ {q, level:"screen"|"onsite"|"senior", answer (model answer, 60–150 words)} ],  // 8–12
  reappears_in: [ {code, how} ],                    // where this course's skills are used elsewhere in the program
  glossary: [ {term, def} ]                         // 10–20
};
```

Depth target per course: 9–10 weeks × 3–5 concepts with code, ≥ 6 widgets, 30+ MCQs,
8–12 interview Q&A, glossary. Pages will be long; that is intended. Every code snippet
is run by `tools/run_snippets.py` and its stdout is stored in `output`, so claims cannot drift.
C++ snippets are compiled with `c++ -std=c++20`; R snippets are allowed only if `Rscript` exists, otherwise use Python.

## Skill tag vocabulary

Kebab-case, shared across all 29 courses. `tools/build_skills.py` collects every tag and
fails if a tag appears in exactly one course *and* is not in `skills_seed.js`'s allow-list
(catches typos and near-duplicates). Categories: `math`, `stats-ml`, `markets`, `pricing`,
`programming`, `data`, `risk`, `trading`. Prefer an existing tag over a new one.

## Widget menu (implemented once in widgets.js; content authors only pass params)

| type | params | typical use |
|---|---|---|
| `payoff` | legs:[{kind:"call"/"put"/"stock"/"bond", strike, qty, premium}], range | options, structured products |
| `binomial-tree` | S0, u, d, r, steps, K, kind | discrete pricing |
| `curve` | series:[{name, x[], y[]}], xlab, ylab, log | yield curves, vol smiles, paths |
| `simulate-paths` | model:"gbm"/"ou"/"heston-lite", params, n_paths, seed, horizon | stochastic processes |
| `histogram` | sampler:"normal"/"t"/"mixture"/"bootstrap", params, bins, overlay | tails, VaR |
| `slider-formula` | formula (KaTeX), inputs:[{name,min,max,step,init}], compute (safe expression string) | Black–Scholes, duration, Kelly |
| `orderbook` | levels, spread, seed | microstructure |
| `heatmap` | matrix, xlabels, ylabels, cmap | correlations, greeks surfaces |
| `regression` | n, beta, noise, seed, show_resid | statistics, factor models |
| `efficient-frontier` | mu[], sigma[], rho, rf | portfolio theory |
| `tree-diagram` | nodes, edges | pipelines, system architecture |
| `timeline` | events:[{t,label}] | course/quarter arcs, trade lifecycle |
| `code-trace` | steps:[{line, state}] | algorithms, C++ memory |

Widgets are SVG, seeded LCG (no `Math.random`), no external libs except KaTeX (CDN, formulas only).

## Page conventions

- Banner on every course page: "Built from the public {institution} course page ({fetched}). The syllabus PDFs are behind a UChicago login, so the week-by-week outline, explanations, code, questions and glossary are the dashboard's own reconstruction of a standard treatment of these topics, not the instructor's material. Corrections welcome: {contact}."
- Accent per concentration (program.js `accent`), neutral slate for status; a course in several concentrations uses the first listed.
- Institution, program name, base URLs, contact only in `site_params.js`; pages carry neutral fallback text in `[data-sp]` nodes.
- No `Math.random`, no external JS except KaTeX, every internal link resolves (validate.py), every page loads with 0 console errors (Playwright sweep).
