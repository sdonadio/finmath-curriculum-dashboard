# FinMath Curriculum Arena

A static dashboard for a whole master's curriculum: a programme map, one deep
page per course, and a shared skill vocabulary that says which course builds
each skill and which course assumes you already have it.

No build step, no framework, no bundler. Every page is plain HTML plus three
ES5 files (`app.js`, `widgets.js`, `styles.css`) and a handful of data files
that are just `window.X = {…}` globals. It runs from GitHub Pages, from any
static server, and — apart from `course.html`, which injects a `<script>` for
the course you asked for — from `file://` as well.

The one hard rule: **`site_params.js` is the only file that names an
institution.** Everything else says "the programme".

---

## The pages

| page | what it is |
|---|---|
| `index.html` | The programme map. Course cards grouped by block, filtered by block / concentration / quarter / skill / free text, each with its own progress. Hover or focus a card for its prerequisites and what it feeds. |
| `course.html?c=FINM-33000` | The deep page. Header and provenance banner, prerequisites and textbooks, skills built and assumed, a brush-up list, a sticky week navigator, then per week: topics, concepts (explanation + KaTeX formula + code with its **real captured output**), an interactive widget, pitfalls, and check-yourself MCQs with feedback. Then interview Q&A, where the course reappears, and a glossary. |
| `concentration.html?c=financial-computing` | One concentration: units, suggested paths, every course that counts, and the skills those courses build. |
| `quarter.html` | The year. One column per quarter, plus a table of every prerequisite edge with the quarter each side is offered in, flagging any that cannot be scheduled in order. |
| `skills.html#<tag>` | The shared vocabulary. Every skill tag, the courses that build it and the courses that assume it, and which tags are assumed but never taught. |

Static wrappers (`course-finm-33000.html`, `concentration-trading.html`) are
generated for deep links, because GitHub Pages has no SPA fallback and a bare
query string on a missing file is a 404.

**Progress** — weeks opened and MCQs answered — lives in `localStorage` under
`<SITE_PARAMS.storage_prefix>:…` and nowhere else. No account, no server, and
nothing an instructor can see.

**Printing** — a course page is designed to be printed as a study guide. Chrome,
filters, the week navigator and every widget *control strip* are hidden; the
widget SVGs, the code, the captured output and the answers are kept, and every
week and interview answer is forced open.

## The files

```
site_params.js        THE ONLY file naming the institution. Also the KaTeX loader
program.js            blocks, concentrations, quarters, components, the course index
courses/finm-*.js     one deep course object each  → window.COURSES["FINM 33000"]
skills.js             GENERATED by tools/build_skills.py — do not hand-edit
data/skills_seed.js   the tag vocabulary: names, categories, the singleton allow-list
data/raw/             the harvested pages the course pages are derived from
app.js                loaders + the five page renderers
widgets.js            the 13 widget types, SVG, seeded LCG, no external libs
styles.css            one stylesheet, dark theme, accent per concentration, print rules
tools/                harvest.py build_skills.py validate.py run_snippets.py
                      make_course_pages.py sweep.py stubs.py jsload.py demo_course.js
```

`SCHEMA.md` is the frozen contract for every data file. Read it before writing
a course; this README only covers the mechanics.

## Adding or refreshing a course

1. **Write `courses/finm-XXXXX.js`** to `SCHEMA.md`. Start from
   `tools/demo_course.js`, which exercises every field and every widget once.
   Leave every `code.output` as `""` — you do not write outputs by hand.

2. **Run the snippets.** This executes every `concepts[].code.src` and splices
   the real stdout back into the sibling `output`, so the page can never claim
   a result its code does not produce.

   ```bash
   python3 tools/run_snippets.py courses/finm-33000.js
   ```

   Python runs under `sys.executable`; C++ compiles with `c++ -std=c++20 -O2`;
   R runs only if `Rscript` exists, and is skipped with a message otherwise
   (`SCHEMA.md` says use Python in that case). Non-zero exit, a timeout,
   anything on stderr, or more than 8 000 characters of output is a failure.

3. **Rebuild the vocabulary.** `skills.js` is generated, and the course pages
   trust it — a course whose file exists but is not in `skills.js` will not
   load. Always rerun this after adding a course:

   ```bash
   python3 tools/build_skills.py
   ```

4. **Validate.**

   ```bash
   python3 tools/validate.py            # 0 errors is the gate
   python3 tools/validate.py --strict   # warnings become errors too
   ```

5. **Regenerate the wrappers** whenever the course list changes:

   ```bash
   python3 tools/make_course_pages.py
   ```

6. **Sweep** — load every page in Chromium, click every control, assert zero
   console errors at 1280px and no horizontal overflow at 390px:

   ```bash
   python3 tools/sweep.py
   ```

The whole loop, in one line:

```bash
python3 tools/run_snippets.py && python3 tools/build_skills.py \
  && python3 tools/validate.py && python3 tools/make_course_pages.py \
  && python3 tools/sweep.py
```

### Testing the shell with no courses written

`tools/demo_course.js` is a complete five-week course using every schema field
and all 13 widget types. Install it, run the loop against it, then take it back
out — `courses/` must not contain it when you publish:

```bash
python3 tools/stubs.py --install        # copies it to courses/finm-00000.js
python3 tools/build_skills.py
python3 tools/validate.py               # expect 0 errors
python3 tools/make_course_pages.py
python3 tools/sweep.py --max-clicks 600 # 600 so the widget controls are all reached
python3 tools/stubs.py --remove
python3 tools/build_skills.py --allow-empty   # do not leave a stale index behind
python3 tools/make_course_pages.py
```

The default `--max-clicks 120` is not enough for the demo course page: its five
weeks hold 13 widgets and around 180 controls between them.

## The tools

| tool | what it does |
|---|---|
| `harvest.py` | Fetches the public course pages into `data/raw/` and writes `program.js`, `site_params.js`, `data/skills_seed.js`, `data/courses.csv`. |
| `run_snippets.py` | Runs every code snippet and writes its real stdout back into `output`. `--check` verifies without writing (use it in CI). `--jobs`, `--timeout`. |
| `build_skills.py` | Generates `skills.js`. **Fails** when a tag is used by exactly one course and is not in the seed's allow-list. Prints near-duplicate suspects by edit distance. `--check`, `--dry-run`, `--distance`. |
| `validate.py` | The schema gate. Every rule in the table below. `--strict`, `--no-site`, `--quiet`. |
| `make_course_pages.py` | Emits `course-<slug>.html` and `concentration-<id>.html` wrappers from the templates, and deletes stale ones. `--dry-run`. |
| `sweep.py` | Playwright smoke test: every page, every control, 0 console errors; second pass at 390px checking for overflow. Exits 2 if Playwright is not installed. `--headed`, `--base`, `--only`, `--max-clicks`. |
| `jsload.py` | Shared reader for the data files. Handles comments, bare keys, trailing commas and — the one that matters — `"a" + "b"` string concatenation, which `json.loads` cannot. |
| `stubs.py` | Installs the demo fixture (and any missing placeholder data) for a test run; `--remove` deletes exactly what it created. |
| `demo_course.js` | The test fixture: `FINM 00000 · Demo Course`, five weeks, every schema field and all 13 widget types. Lives in `tools/`, never in `courses/`. |

### What validate.py enforces

**Per course file**

- exactly one `window.COURSES["CODE"] = {…}` per file
- every required field present and correctly typed (19 of them)
- the file name, the `slug` and the `code` all agree; slug is kebab-case
- `source.page_url` / `source.syllabus_url` are http(s); `source.fetched` is an ISO date; `tier` is one capital letter
- `block`, `quarter` and every `concentrations` id resolve against `program.js` (an unlisted quarter warns — `program.js` itself carries values like "September Launch")
- week count is **5, or 9–10**; week numbers are `1..n` with no gaps or repeats
- **≥ 3 concepts per week** (more than 5 warns)
- every concept has `name`, `explain` and `code{lang,src,output}`; `lang` in python/cpp/r; the `output` **key** must exist; `explain` outside 150–300 words warns
- **a widget on ≥ 60 % of weeks**; every widget type is one `widgets.js` actually registers (read from `widgets.js`, so the two cannot drift); every widget has a title and a `params` object
- **3–4 MCQs per week**, exactly 4 options, no duplicate or empty options, `answer` an integer index in range, `why` present (under 20 words warns)
- **2–4 pitfalls** per week
- **8–12 interview items**, `level` in screen/onsite/senior, answer 60–150 words (warns outside)
- **10–20 glossary** entries with term and definition; **4–8 brush-up** items
- every skill tag is kebab-case and resolves — in `skills.js`, in the seed, or used by ≥ 2 courses; duplicates and build/assume overlap are reported
- every `reappears_in` code resolves to a course in `program.js`, and says *how*
- **no `Math.random`, no `eval(`, no `new Function`**
- **the institution string appears in no file but `site_params.js`** (URLs are exempt — a source link necessarily contains the domain)
- every relative path the file mentions exists on disk

**Site-wide**

- the five templates exist and each carries `body[data-page]`
- every `href`/`src` in every `.html` resolves (query and hash stripped)
- `app.js`, `widgets.js`, `styles.css` exist; the two JS files pass `node --check`
- no banned construct and no institution string in any shipped `.js`
- every course in `program.js` has a file (warning) and every file is in `program.js` (error — an orphan page is unreachable from the map)

## The widget menu

All 13 are implemented once in `widgets.js` and driven entirely from
`{type, title, params}`. They are SVG, seeded by an LCG (never `Math.random`),
responsive, and they never throw: a bad type or a malformed parameter renders a
readable note instead of breaking the page. KaTeX is used for `formula` strings
only, is loaded from a CDN by `site_params.js`, and degrades to monospace TeX
when it is absent — so the site works offline.

| type | what its controls do |
|---|---|
| `payoff` | Spot slider drops a marker and reads the net P&L there; a Net / Net + legs switch shows or hides the individual legs; an "Include premium" toggle flips between expiry payoff and P&L. Breakevens, strikes and the profit/loss shading move with it. |
| `binomial-tree` | Sliders for steps, `u` (with `d = 1/u` unless given) and `r`; selects for call/put, European/American, and whether each node shows the stock or the option. Prices the full tree, draws the first six steps. |
| `curve` | One chip per series toggles it on and off; a "Log y" switch (falling back to linear with a note if any value ≤ 0); a crosshair slider moves a vertical rule and reads every visible series into the stat strip. |
| `simulate-paths` | Sliders for path count, the model's volatility parameter and the horizon; a "Mean ± 1 sd band" toggle; a Reseed button. `heston-lite` adds a variance-path panel. |
| `histogram` | Selects the sampler (normal / t / mixture / bootstrap); sliders for bins, sample size and the tail quantile (drawn and shaded); a normal-density overlay toggle and Reseed. Reads out mean, sd, skew, excess kurtosis, VaR and ES. |
| `slider-formula` | One slider per declared input, plus Reset. The KaTeX formula sits above, every `compute` statement gets a stat, and a 120-point sensitivity curve sweeps the first input with a marker at its current value. Expressions run through a tokenizer → shunting-yard → RPN machine — never `eval`. |
| `orderbook` | Sliders for levels, spread in ticks, book imbalance and sweep size, plus Reseed. Reads out mid, spread, microprice, OBI and the VWAP and slippage of the sweep. |
| `heatmap` | A colour-map select (diverging / sequential / mono), a clamp slider that saturates the scale, and a "Show values" toggle. |
| `regression` | Sliders for n, the true beta and the noise level; toggles for residual stems (plus a residual panel) and for adding a high-leverage outlier; Reseed. Reports beta-hat, its standard error, t and R². |
| `efficient-frontier` | Sliders for the correlation (clamped to stay positive definite, with a note) and the risk-free rate; toggles for short-selling and for a cloud of random portfolios. Draws the frontier, the capital allocation line and the tangency point. |
| `tree-diagram` | A Left→right / Top→bottom switch, and a node select that highlights that node and every edge and ancestor path reaching it. Depth is computed from the edges. |
| `timeline` | A zoom slider sets the visible span; Prev / Next step the highlighted event and read its label and note into the stat strip. `t` may be a number or an ISO date. |
| `code-trace` | A step slider plus ◀ / ▶ and Restart — no timer. The current line is highlighted in the source and the state table marks every binding that changed since the previous step. |

## Publishing

1. `python3 tools/stubs.py --remove` — the demo fixture must not ship.
2. Run the whole loop above; `validate.py` must report **0 errors** and
   `sweep.py` **0 failures**.
3. Commit everything, including `data/raw/` (see below).
4. Push. `.nojekyll` is already present, so GitHub Pages serves the files
   verbatim — without it, Jekyll would ignore any path starting with `_` and
   rewrite things it should not.
5. Settings → Pages → deploy from the branch root.

`site_params.site_url` should match where it lands.

### Harvested data

`data/raw/` is committed on purpose: every course page cites what it was
derived from, and a citation you cannot check is not a citation. It is about
1 MB today. If it ever grows past 40 MB, add `data/raw/pdf/` to `.gitignore`
and note it here — a Pages repo carrying tens of megabytes of binaries makes
every clone slow for everyone.

## Stubs

`program.js`, `site_params.js` and `data/skills_seed.js` are written by the
harvest step, and the course files by the content step. Before those exist the
pages still render — `app.js` treats every data file as optional — but the
browser logs a 404 for each missing `<script src>`, and `sweep.py` fails a page
on any console error. `tools/stubs.py --install` fills the gaps so the smoke
test can run; it never overwrites a real file, and `--remove` deletes exactly
what it created (tracked in `.stubs-installed`).

Today only the demo fixture is stubbed, since the real data files have landed.
A stub is self-identifying: it carries `stub: true`, and `app.js` shows an amber
"stub data" strip on any page built from one.

## Ambiguities in SCHEMA.md, and how they were resolved

`SCHEMA.md` is frozen, so nothing below changes what a content author must
write. These are places where it was silent and the shell had to choose.

1. **`program.js` has no drawn course index.** SCHEMA calls `program.js` the
   "course index" but its sketch only shows `blocks[].courses` as bare codes,
   which carry no title, quarter or units. `app.js` reads an optional
   `PROGRAM.courses` array of `{code, slug, title, instructor, quarter, units,
   block, concentrations, tier, blurb}` when present, and otherwise rebuilds a
   thin index from the block and concentration membership lists. The harvest
   agent supplies it; without it the map has codes and nothing else.

2. **`data/skills_seed.js` has no declared shape.** `build_skills.py` accepts
   three: `tags` as an object, `tags` as an array, or the whole seed keyed by
   category (`{math: [{tag, name}], pricing: […]}`), which is what the harvest
   writes. With no `allow` key, every seeded tag is allowed to be a singleton —
   the seed is then simply the allow-list. A single `name` longer than ~48
   characters is read as a blurb, because the harvest seed writes one
   descriptive sentence per tag rather than a short label.

3. **One widget per week, but 13 widget types.** SCHEMA says
   `widget: {…} | null`. That is what a real course writes. The shell
   *additionally* accepts an array of widget specs, used only by
   `tools/demo_course.js`, which has to show all 13 types in five weeks.
   `validate.py` counts a week as having a widget either way.

4. **`compute` as a "safe expression string".** `slider-formula` accepts a
   single expression or an ordered array of `{name, expr, label, fmt}`
   statements, where later ones may use earlier names and the last is the
   primary output — Black-Scholes needs `d1`, `d2`, then the price. "Safe" is
   implemented as a tokenizer, a shunting-yard parser and an RPN evaluator; no
   `eval` and no `new Function` appear anywhere in the repository, and
   `validate.py` greps for both.

5. **Depth targets: error or warning?** Hard structural counts — week count,
   concepts per week, MCQs per week, options per MCQ, interview items, glossary
   and brush-up sizes, widget coverage — are **errors**. Prose-length bands
   (`explain` 150–300 words, interview answers 60–150) are **warnings**,
   promoted to errors by `--strict`. A word count is a style target; failing a
   build on one would be brittle.

6. **A course whose deep page is not written yet.** `program.js` lists 29
   courses long before 29 files exist. `app.js` does not even attempt to fetch
   `courses/<slug>.js` when `skills.js` — which is generated from the files
   that actually exist — says there is none; it renders a "not written yet"
   page instead. This is why `build_skills.py` must be rerun after adding a
   course, and why a missing `skills.js` makes the page try the fetch anyway.

7. **Provenance and the institution rule.** The banner wording is quoted from
   SCHEMA, but it mentions the school twice, and only `site_params.js` may name
   one. Both mentions are read from `SITE_PARAMS.institution` and
   `.institution_short` at render time, so the literal string never appears in
   `app.js` and `validate.py`'s leak check stays green.

8. **"Every internal href resolves."** Enforced as: every `href`/`src` in every
   `.html` (query and hash stripped) must exist on disk, and any relative
   `.html`/`.js`/`.css`/`.pdf` path mentioned inside a course file must too.
   Generated files that may legitimately not exist yet (`program.js`,
   `skills.js`, `site_params.js`) warn rather than fail.

## Requirements

- Python 3.11 for the tools (standard library only, except Playwright)
- `playwright` + `playwright install chromium` for `tools/sweep.py`
- a C++20 compiler if any course uses a `cpp` snippet
- `Rscript` only if a course uses an `r` snippet; otherwise those are skipped
- `node` is optional — `validate.py` uses it to syntax-check `app.js` and
  `widgets.js`, and warns when it is missing
